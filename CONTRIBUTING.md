# Contributing

Keep each tool focused on one review decision. Preserve unknowns, the fictional-example flag and the distinction between a user assertion and verified evidence.

Use a pull request to explain the changed behavior and its tests. Do not submit credentials, customer records, patient information, private contracts or real review exports. Use invented fixtures. Report a security concern without including exploit credentials or personal data in a public issue.

Keep browser workflows local by default. Any network integration needs an explicit data-flow design and permission review. Do not add analytics or automatic approval scores.

Use Radley for headings, Roboto for body/UI, orange #FF7900 and cyan #07A3D1. Keep readable labels and keyboard controls; do not communicate a state through color alone.

Include source dates and scope for factual changes. Keep third-party notices. Contributions should be compatible with the repository's Apache-2.0 license. Do not imply endorsement, regulatory approval or evidence that was not supplied.

Update the release notes and tests when behavior or public artifacts change. Increment package versions for changed downloads instead of replacing a published archive under the same version.
